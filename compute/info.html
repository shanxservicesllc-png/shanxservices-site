Info & Safety

What gets processed?

When you opt in, the browser requests approved tasks from the X13 coordinator running on MONSTER. Currently approved research tasks include checking citation metadata for repeats and ranking existing public research titles. Results are independently checked by MONSTER before being counted. When no useful approved task exists, the worker waits for new work rather than generating filler activity.

Permission and controls

Press Start to authorize contributions for that browser. A later visit may auto-start while that permission remains saved. Press Stop or Disable auto-start to revoke it. Each browser has its own permission. Closing the page ends the browser worker. The page is not an invisible background service.

CPU, GPU and memory

The slider controls a conservative target for a single browser CPU worker, not a guaranteed percentage of the device's total processor, GPU or RAM. On a typical phone, 100% corresponds to a provisional 15% single-thread duty-cycle cap. Eligible numerical tasks may use WebGPU; unsupported browsers fall back to CPU. Neither a GPU feature nor a VRAM allocation can be guaranteed. The system does not intentionally fill available RAM or VRAM.

Battery, network and background activity

Battery use, mobile data use, and some device warmth are possible. The worker pauses for low battery when the browser exposes that information. Android may throttle or suspend hidden browser tabs; the native Android app has a visible foreground notification and OS-imposed limits. Do not leave the device unattended if it becomes uncomfortably hot or behaves unexpectedly.

Privacy and server access

The Infinity Box displays approximate browser/device details locally. Public citation metadata and numerical results travel through HTTPS to MONSTER for verification; personal files, camera, contacts and passwords are not part of approved workloads. Operators can submit only allowlisted work types. The current backend uses a temporary Cloudflare tunnel, which is not permanent hosting and has no guaranteed uptime. This system does not pool GPU memory between devices into one large accelerator.

Current limitations

There is no unlimited supply of unique research tasks. The connection keeps polling while allowed, but completed tasks only increase when new, approved useful work is ready. A browser's running time reflects an authorized connection session, not 100% active CPU time. Results are not automatically counted as new RABBITRY searches or as progress toward its consecutive dry-search criterion.
